# AGENTS.md — opentargets-link

Guidance for agents and contributors working in this repository.

> `README.md` is the front door and follows the **GeneFoundry README Standard v1** (hard
> ceiling 200 lines, fixed section order, machine-checked by `scripts/check_readme.py`).
> Depth lives in `docs/`. Do not grow the README: relocate.

## What this is

`opentargets-link` is a read-only MCP server over the **Open Targets Platform**
(`https://api.platform.opentargets.org/api/v4/graphql`, CC0): target tractability, ChEMBL drug
and clinical candidates, disease→target association ranking and target–disease evidence. It is
one backend in the GeneFoundry `-link` fleet, federated behind `genefoundry-router` under the
namespace **`opentargets`**. Scaffolding (MCP plane, Docker, CI) was cloned from
`pgscatalog-link` via `civic-link`. Do not federate `opentargets/platform-mcp` (raw GraphQL
passthrough). Tracking issue:
https://github.com/berntpopp/genefoundry-router/issues/349.

## Two planes (non-negotiable boundary)

- **Data plane** — `config.py`, `ratelimit.py`, `api/`, `queries.py`, `service.py`,
  `shaping.py`. Calls Open Targets over async httpx, validates arguments, returns **plain dicts**,
  raises typed `opentargets_link.exceptions` errors. Never builds envelopes.
- **MCP plane** — `mcp/`. `run_mcp_tool` (`mcp/envelope.py`) owns `success`/`_meta` and turns
  exceptions into **returned** `isError` envelopes (never raised to the client).

## Invariants

- **Live API only, no data snapshot.** Nothing is stored beyond the in-process TTL cache in
  `api/client.py`.
- **Fixed GraphQL documents only** (`queries.py`). Never accept caller GraphQL. Variables are
  named after the tool parameter they carry so a `Variable '$x'` error names `x`.
- **GraphQL errors arrive as HTTP 200 or 400 + `errors[]`.** The client maps them to typed
  errors; `Cannot query field` is schema drift. Upstream text is never echoed.
- **Datasource ALLOWLIST** (`datasources.py`, guarded by `tests/test_datasources.py`). Never
  serve `cancer_gene_census`, `genomics_england`, `crispr`, `europepmc` or the held
  `cancer_biomarkers`; never query `Target.hallmarks` (COSMIC). Association scores pass every
  excluded datasource at weight 0. Adding a datasource is a licence decision.
- **Schema drift.** `TESTED_DATA_VERSION` (`mcp/capabilities.py`) is the release the queries
  were verified on; the live integration test fails when Open Targets ships a new release or a
  query stops validating. Re-verify and bump it per quarterly release.
- **Unknown IDs are `not_found`.** Open Targets answers `null` for an unknown ID; the data plane
  maps it to `not_found` naming the argument. HGNC/NCBI gene IDs and OMIM/DOID disease IDs are
  `invalid_input` with a converter (`hgnc_resolve_symbol`, `mondo_resolve_disease`).
- **Paging.** Offsets for drugs/associations (window ≤ 3,000), Open Targets' cursor for
  evidence; `truncated` is computed from the count, not from the presence of a cursor.
- **Bounded drugs.** `clinicalReports` is selected only in `response_mode="full"` (top 3/drug).
- **Assemblies.** Variant IDs and target locations are GRCh38 and say so.
- **Empty is not negative.** Zero rows says "no Open Targets data found", never "not druggable".
- **Politeness.** Every upstream request passes the process-wide `RateLimiter` (default 0.34 s
  spacing ≈ 3 req/s, 20,000/UTC day). Do not bypass it, including in live tests.
- **Untrusted text.** Mechanism-of-action strings and clinical-report titles are fenced with
  `fence_untrusted_text`.
- **6-code error taxonomy**: `invalid_input`, `not_found`, `ambiguous_query`, `rate_limited`,
  `upstream_unavailable`, `internal`.
- Tools publish no `outputSchema` (Tool-Surface Budget Rule 3); every input property has a
  description, required ones carry `examples`, closed vocabularies are `Literal` enums.
- Keep `mcp/capabilities.py::TOOLS` equal to the registered tool set and the README `## Tools`
  table in sync (both tested).

## Fleet deploy contract

`docker/docker-compose.npm.yml` (deployed by the fleet controller `strato_v6_docker_npm`)
declares `user: "10001:10001"` — this image's own uid:gid from `docker/Dockerfile`. `user` must
NOT appear in `docker/docker-compose.yml` / `docker/docker-compose.prod.yml` (the release gate
forbids it). Guard: `tests/unit/test_deploy_overlay_user.py`. Both reusable-workflow pins
(`container-ci.yml`, `container-release.yml`) track the same `genefoundry-router` revision.

Release checklist: bump `pyproject.toml`, `uv lock`, `CHANGELOG.md` heading
`## [x.y.z] - YYYY-MM-DD`, `CITATION.cff` `version:` (generated by the router's
`make citation-write`), tag `vx.y.z`, approve the `release` environment gate via
`gh api repos/berntpopp/opentargets-link/actions/runs/<id>/pending_deployments` (it can gate more than
once). **Never `gh release create`** — the workflow creates the immutable release.

## Definition of done

`make ci-local` green: format-check, lint-ci, lint-loc (≤500 lines/file), lint-readme,
lint-surface, mypy `--strict`, tests. Unit tests are network-free: `respx` replays recorded
Open Targets responses. Live checks are opt-in
(`make test-integration`, a handful of polite calls).

## Make targets

```
make install          # uv sync --group dev
make ci-local         # the definition-of-done gate
make test             # unit tests
make test-integration # live Open Targets calls (opt-in, rate-limited)
make dev              # unified HTTP server on 127.0.0.1:8000
make mcp-serve        # stdio MCP server
make docker-up        # Docker stack; make docker-url prints the MCP URL
```

## Conventions

- Python 3.14, `uv`, hatchling; structlog to **stderr only** (stdout is the stdio protocol).
- TDD: failing test first. Files under 500 lines.
- `tests/conformance/` and `scripts/check_readme.py` / `scripts/surface.py` are vendored
  byte-identical from `genefoundry-router`; do not edit them here.
