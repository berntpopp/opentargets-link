# Deployment

## Docker

The image ships no data and keeps no on-disk state: every tool calls the live Open Targets
GraphQL API and responses are cached in-process only (TTL). The production overlays run it
with a read-only root filesystem and a tmpfs. There are no volumes and no sidecars.

```bash
# Local dev (loopback-published, builds from source)
make docker-build && make docker-up && make docker-url

# Production (nginx-proxy-manager overlay, pulls the released digest)
GF_IMAGE=ghcr.io/berntpopp/opentargets-link@sha256:<digest> \
  docker compose -f docker/docker-compose.npm.yml --env-file .env.docker up -d
curl -fsS -H 'Host: localhost' http://127.0.0.1:8000/health
# → {"status": "ok", "version": "...", "capabilities_version": "..."}
```

## Fleet deploy contract

`docker/docker-compose.npm.yml` is the Compose file the GeneFoundry fleet controller
(`strato_v6_docker_npm`) deploys and validates. It declares `user: "10001:10001"` --
this image's own numeric uid:gid, read from `docker/Dockerfile`'s
`groupadd --gid 10001 app && useradd --uid 10001 --gid app ...`; the controller's
runtime observer proves the effective uid from `/proc`, so the declared value must
be numeric, not the account name. `user` must NOT appear in `docker/docker-compose.yml`
or `docker/docker-compose.prod.yml` -- those are the Compose files listed in
`container-release.json`, and the shared release gate (`container_release.py
validate-compose`) forbids `user` on them. `tests/unit/test_deploy_overlay_user.py` guards
both halves of this contract.

`container-release.json` also declares `service.deployed_compose_files:
["docker/docker-compose.npm.yml"]` -- the exact file the controller deploys. Per the Deploy
Contract Standard v1 its image is `${GF_IMAGE}` and, as a single service, it joins only the
external proxy network (no project network, so no subnet from the C6 registry).
Both reusable-workflow pins (`.github/workflows/container-ci.yml`,
`.github/workflows/container-release.yml`) must track the same
`genefoundry-router` revision (`tests/test_workflow_pins.py`): the shared
`_container-release.yml` workflow runs `container_release.py
validate-deployed-overlay` against the declared file before every release,
and `_container-ci.yml` loads the same `ReleaseConfig` schema from its own
pin to validate this JSON, so an older pin there rejects new fields.

Release checklist: bump `pyproject.toml` `version`, run `uv lock`, add a
`CHANGELOG.md` heading `## [x.y.z] - YYYY-MM-DD`, bump `CITATION.cff` `version:`
(generated by `make citation-write` in genefoundry-router) -- tag `vx.y.z`, then approve
the `release` GitHub Environment gate (it can fire more than once) via `gh api
repos/berntpopp/opentargets-link/actions/runs/<id>/pending_deployments`
(`status: waiting` is the gate).

Self-check that the controller can render and project this overlay:

```bash
GF_IMAGE="ghcr.io/berntpopp/opentargets-link@sha256:<64 hex>" docker compose -f docker/docker-compose.npm.yml config --format json > /tmp/r.json
# from strato_v6_docker_npm: uv run python -c "import sys,json; sys.path.insert(0,'scripts'); from utils.deployment_preflight import canonical_projection; canonical_projection(json.load(open('/tmp/r.json')), project='opentargets-link'); print('PROJECTION OK')"
```

## Configuration (environment variables)

All settings use the `OPENTARGETS_LINK_` prefix; nested models use `__` as the delimiter.
Copy `.env.docker.example` to `.env.docker` and set the values for your deployment.

### Server settings

| Variable | Default | Purpose |
|----------|---------|---------|
| `OPENTARGETS_LINK_HOST` | `0.0.0.0` | Bind host (use `127.0.0.1` behind a reverse proxy). |
| `OPENTARGETS_LINK_PORT` | `8000` | Bind port. |
| `OPENTARGETS_LINK_TRANSPORT` | `unified` | `unified` \| `http` \| `stdio`. |
| `OPENTARGETS_LINK_MCP_PATH` | `/mcp` | MCP endpoint mount path (must start with `/`). |
| `OPENTARGETS_LINK_ALLOWED_HOSTS` | `["localhost","127.0.0.1","::1"]` | Exact HTTP Host allowlist as JSON; wildcards are rejected. |
| `OPENTARGETS_LINK_ALLOWED_ORIGINS` | `[]` | Exact browser Origin allowlist as JSON. |
| `OPENTARGETS_LINK_CORS_ORIGINS` | `""` | Comma-separated allowed CORS origins. |
| `OPENTARGETS_LINK_LOG_LEVEL` | `INFO` | `DEBUG`…`CRITICAL`. Logs go to stderr. |
| `OPENTARGETS_LINK_LOG_FORMAT` | `console` | `console` (dev) \| `json` (prod). |

Browser deployments must configure the same exact origins in
`OPENTARGETS_LINK_ALLOWED_ORIGINS` and `OPENTARGETS_LINK_CORS_ORIGINS`; the strict
transport guard and browser CORS are independent controls.

### Open Targets upstream (`OPENTARGETS_LINK_OPENTARGETS__*`)

| Variable | Default | Purpose |
|----------|---------|---------|
| `OPENTARGETS_LINK_OPENTARGETS__BASE_URL` | `https://api.platform.opentargets.org` | Open Targets Platform GraphQL API base URL (only this origin is ever contacted). |
| `OPENTARGETS_LINK_OPENTARGETS__REQUEST_TIMEOUT_S` | `20.0` | Per-request timeout. |
| `OPENTARGETS_LINK_OPENTARGETS__MIN_INTERVAL_S` | `0.3` | Process-wide spacing between upstream requests (about 200/min). |
| `OPENTARGETS_LINK_OPENTARGETS__DAILY_CAP` | `20000` | Upstream requests per UTC day; beyond it tools answer `rate_limited`. |
| `OPENTARGETS_LINK_OPENTARGETS__MAX_WAIT_S` | `20.0` | Longest queue wait for a request slot before answering `rate_limited` with `retry_after_s`. |
| `OPENTARGETS_LINK_OPENTARGETS__MAX_RETRIES` | `2` | Retries on 429/5xx/timeouts (exponential backoff, honours `Retry-After`). |
| `OPENTARGETS_LINK_OPENTARGETS__BACKOFF_BASE_S` | `2.0` | Backoff base (seconds). |
| `OPENTARGETS_LINK_OPENTARGETS__MAX_RESPONSE_BYTES` | `16777216` | Hard cap on one upstream body (fail closed). |
| `OPENTARGETS_LINK_OPENTARGETS__CACHE_TTL_S` | `900` | In-process response cache TTL. |
| `OPENTARGETS_LINK_OPENTARGETS__CACHE_MAXSIZE` | `512` | In-process response cache entries. |

**Why 0.3 s.** Open Targets publishes no request limit (none found 2026-11-20); 0.3 s spacing
(~200/min) is a conservative choice for an academic service. The limiter is per process: run
one replica, or divide the budget between replicas. Open Targets silently caps a GraphQL page at 100
nodes; the tools cap `limit` at or below that, so `total`/`truncated` stay honest.

### Live integration checks

`make test-integration` makes a handful of real calls through the same limiter (opt-in, never
in CI).

## Transports

Three transports, selected with `--transport` or `OPENTARGETS_LINK_TRANSPORT`.

| Transport | Serves | MCP endpoint? |
|-----------|--------|---------------|
| `unified` (default) | FastAPI `/health` + MCP `/mcp` on one port | **yes** — `/mcp` |
| `http` | FastAPI/REST **only** | **NO** |
| `stdio` | MCP over stdin/stdout (Claude Desktop) | yes (stdio framing) |

> **Footgun.** `--transport http` is REST/FastAPI-only: it does **not** mount the MCP app, so
> there is no `/mcp` endpoint. An MCP client (or the GeneFoundry router) pointed at an `http`
> server will fail to connect. Use `unified` for MCP over HTTP.

In `unified` mode the server mounts the MCP Streamable-HTTP ASGI app alongside the FastAPI
application on one port:

```
:8000
  GET  /health   → FastAPI health endpoint (capabilities_version, status)
  *    /mcp      → FastMCP Streamable-HTTP
```

This is the transport the GeneFoundry router uses — it proxies the `/mcp` endpoint as
`https://opentargets-link.genefoundry.org/mcp`.

## MCP client configuration

**HTTP (Streamable HTTP).** Start the server in `unified` mode, then register the `/mcp` URL:

```bash
uv run opentargets-link                    # unified, :8000
claude mcp add --transport http opentargets-link --scope user http://127.0.0.1:8000/mcp
```

**Stdio** (Claude Desktop / Claude Code). Uses the dedicated `opentargets-link-mcp` entry point;
stdout is reserved for the protocol, so logs go to stderr only:

```json
{
  "mcpServers": {
    "opentargets-link": {
      "command": "uv",
      "args": ["run", "opentargets-link-mcp"],
      "cwd": "/path/to/opentargets-link"
    }
  }
}
```

## GeneFoundry router registration

`servers.yaml` entry (router side):

```yaml
  - name: opentargets
    repo: berntpopp/opentargets-link
    url_env: GF_OPENTARGETS_URL
    namespace: opentargets
    entrypoints: [resolve_target]
```

with `GF_OPENTARGETS_URL=https://opentargets-link.genefoundry.org/mcp`.
